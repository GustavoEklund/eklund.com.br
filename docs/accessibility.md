# Accessibility

This page says how the site meets WCAG 2.2 level AA and the WAI-ARIA Authoring Practices, what an automated check covers, and what only a person can judge. It claims no more than the evidence below. Nobody has run a screen reader over every flow, so "conformant" here means "no failure found by the checks listed", not "audited by a specialist".

## How to run the checks

| Command                                          | What it runs                                                                                                                             | Needs                                                         |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `pnpm run validate:html`                         | The W3C Nu HTML Checker on `source/index.html` as shipped and on the DOM the scripts build (pt-BR and en-US, trace and palette rendered) | Java 17 or newer, the Playwright Chromium                     |
| `pnpm run a11y`                                  | Playwright specs `accessibility` (axe-core), `aria-patterns` and `wcag22`                                                                | Playwright Chromium (`pnpm exec playwright install chromium`) |
| `pnpm run contrast`                              | Contrast of every text and non-text color pair, 361 hues in both themes (`tools/contrast-audit.mjs`)                                     | Node                                                          |
| `pnpm run lint:css`                              | Stylelint over the CSS                                                                                                                   | Node                                                          |
| `pnpm run test:contract`                         | Includes the i18n, fonts, JSON-LD, security header and `validate-html` tool contracts                                                    | Node, Java for the tool contract                              |
| `pnpm run test:component` and `test:integration` | Unit-level checks of every widget below (keys, roles, states, announcements)                                                             | Playwright Chromium                                           |

The axe-core runs use the tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa` and `best-practice`, in both themes, both languages, on the desktop and the phone project, and in these states: palette open, shader dialog open, trace span selected, trace zoomed, a job card open, all cards closed (phone), service list open, dashboard table open, motion paused, a map tooltip shown (desktop), and after a full load test run (desktop).

## Patterns from the WAI-ARIA Authoring Practices

| Pattern                                         | Where                                         | Notes                                                                                                              |
| ----------------------------------------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |
| Skip link, landmarks                            | Whole page                                    | Skip link targets `main`, which takes focus.                                                                       |
| Toggle button                                   | Theme and motion buttons                      | `aria-pressed`; the name never changes with the state.                                                             |
| Links to the versions of a page                 | Language links in the header                  | One link per language to its own page, with `hreflang` and `lang`; `aria-current` marks the current one.           |
| Slider                                          | Hue, speed and point multiplier               | `role="slider"` with `aria-valuenow` and `aria-valuetext`; arrows, Page, Home and End.                             |
| Combobox with listbox popup (list autocomplete) | Command palette                               | The input keeps focus; `aria-activedescendant` follows the options; `aria-expanded` is false when nothing matches. |
| Dialog (modal)                                  | Palette and shader code, as native `<dialog>` | Focus moves in, stays in, returns to the opener.                                                                   |
| Accordion                                       | Job cards                                     | Heading, button, `aria-expanded`, `aria-controls`; closed panels are hidden from assistive technology.             |
| Disclosure                                      | Dashboard table, service list                 | Native `<details>`.                                                                                                |
| Listbox                                         | Trace spans                                   | Single selection, `aria-activedescendant`, details in a polite live region.                                        |
| Live regions                                    | Announcer, followed Pix, trace details        | Polite; messages queue and stale counts are replaced.                                                              |

## Known limitations

- No screen reader speech was tested. Roles, names and states are checked through the accessibility tree.
- The `mailto:` links copy the address when clicked, and open the mail client with Ctrl or Cmd held.
- `vnu` reports one warning that is allowed on purpose: the ARIA 1.2 combobox points `aria-activedescendant` at an option that is not its descendant. The tool lists the reason.
- The CSS validator inside `vnu` is not used because it predates `animation-timeline`, `@starting-style` and other features the site uses; Stylelint checks the CSS.
